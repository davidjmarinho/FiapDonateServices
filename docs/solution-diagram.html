Diagrama da solução

Visão de ponta a ponta do fluxo da plataforma: autenticação via Users, criação de campanha, envio de doação ao Receiver, mensageria com RabbitMQ, processamento assíncrono no Worker, persistência em SQL Server e banco auxiliar do Receiver em PostgreSQL. A mesma base também cobre observabilidade com Prometheus e Grafana, além do ambiente em Kubernetes.

Fluxo principal Postman / Swagger → APIs → RabbitMQ → Worker → Banco
Infraestrutura Kubernetes, SQL Server, PostgreSQL e RabbitMQ
Observabilidade Prometheus + Grafana

Fluxo da aplicação

As setas mostram o caminho da requisição e o processamento assíncrono da doação.

Cliente / Postman APIs do domínio RabbitMQ / fila Bancos de dados Observabilidade Kubernetes / CI
Fluxo principal

O usuário autentica, cria a campanha, envia a doação e o Worker atualiza o valor arrecadado de forma assíncrona após a mensagem sair do RabbitMQ.

Base de dados

As APIs usam SQL Server em FiapDonateDb. O Receiver usa PostgreSQL para o banco auxiliar do fluxo de doações.
